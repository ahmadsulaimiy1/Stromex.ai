# StromeX Android — Build Documentation

## What this is

`apps/android/` is a native Android application — a single-Activity WebView
shell (`ai.stromex.app.MainActivity`) that loads the same static-exported
Next.js bundle used by the web app (`apps/web`), served from a virtual HTTPS
origin (`https://stromex.local`) rather than `file://`. It talks to the real
StromeX FastAPI backend over normal HTTPS/HTTP `fetch()` calls, exactly like
the browser app does.

It was built with raw Android SDK command-line tools (`javac`, `d8`, `aapt2`,
`zipalign`, `apksigner`, `bundletool`, `jarsigner`) rather than Gradle/AGP.
**Why:** the sandbox this was originally built in has an outbound network
allowlist that blocks all of Google's Android/Maven infrastructure
(`dl.google.com`, and `maven.google.com`, which itself 301-redirects every
real artifact request to `dl.google.com`). The Android Gradle Plugin itself
must be downloaded from that blocked host, so **no Gradle-based Android
build — Capacitor-based or otherwise — is possible in that environment**,
confirmed by an actual `./gradlew assembleDebug` failure:

```
Caused by: org.gradle.internal.resource.transport.http.HttpErrorStatusCodeException:
Could not GET 'https://dl.google.com/dl/android/maven2/com/android/tools/build/gradle/8.13.0/gradle-8.13.0.pom'.
Received status code 403 from server: Forbidden
```

`apps/android/build.sh` has no such dependency: every tool it calls is either
bundled with the SDK's `build-tools/` or a standalone jar. It builds and runs
identically in a normal, unrestricted environment with a standard SDK
install — nothing about it is sandbox-specific.

There is also a second, more conventional project at `apps/web/android/`,
generated by `npx cap add android` (Capacitor). It is kept as source because
it is the more maintainable long-term path (Capacitor gives you
`WebViewAssetLoader`, splash screens, native plugins, standard Play Store
tooling) — but it could not be built or tested in this environment for the
exact reason above, and its `google()` Gradle repositories were patched to an
explicit `https://maven.google.com/` URL that still resolves to the blocked
host. **Treat `apps/web/android/` as unverified reference source**; in any
environment with normal internet access, `cd apps/web/android && ./gradlew
assembleRelease` should work with standard AGP tooling.

## Toolchain used (apps/android/build.sh)

| Tool | Purpose | Source |
|---|---|---|
| `javac` | Compile `MainActivity.java` | JDK (any JDK 17+works; built with OpenJDK 21) |
| `d8` (via `r8lib.jar`) | Convert `.class` → `.dex` | `storage.googleapis.com/storage/v1/b/r8-releases/o/raw%2F8.5.0-dev%2Fr8lib.jar` |
| `aapt2` | Compile/link resources, manifest, assets | Android SDK `build-tools/` |
| `zipalign`, `apksigner` | Align and sign the APK | Android SDK `build-tools/` |
| `bundletool` | Build/sign/validate the `.aab` | `github.com/google/bundletool/releases` (v1.18.1) |
| `keytool`, `jarsigner` | Generate the signing key; sign the `.aab` | JDK |
| `android.jar` (API 34) | Compile-time framework stubs | `raw.githubusercontent.com/Sable/android-platforms` |

None of these come from `dl.google.com`/`maven.google.com` — that's what
makes this pipeline possible in a network-restricted environment. The app
itself only imports `android.app.*` and `android.webkit.*` — no AndroidX,
because AndroidX artifacts are Google-Maven-exclusive and unreachable in the
original build environment.

## Building

```bash
export ANDROID_HOME=/path/to/android-sdk   # needs platforms/android-34/android.jar
                                            # and build-tools/34.0.0/{aapt2,zipalign}
# Optional overrides (defaults shown):
export BUILD_TOOLS_VERSION=34.0.0
export PLATFORM_VERSION=34
export R8_JAR=/opt/android-tools/r8lib.jar
export BUNDLETOOL_JAR=/opt/android-tools/bundletool.jar

# 1. Build the web bundle the WebView will load
cd apps/web
CAPACITOR_BUILD=1 NEXT_PUBLIC_API_URL=https://your-backend.example.com npm run build
cp -r out/* ../android/assets/

# 2. Build the Android app
cd ../android
./build.sh
```

Output:
- `apps/android/release/stromex-v<version>.apk` — signed, installable release APK
- `apps/android/release/stromex-v<version>.aab` — signed Android App Bundle

`build.sh` also generates `apps/android/keystore/stromex-release.keystore` on
first run (gitignored — **never commit signing-key material**; see the
Signing section below) and runs `apksigner verify` / `bundletool validate`
on its own output before finishing, so a broken build fails loudly rather
than producing a silently-invalid artifact.

## Signing

`build.sh` auto-generates a throwaway release keystore
(`apps/android/keystore/`, gitignored) on first run so the pipeline works
out of the box. **This is fine for sideloading and internal testing, but not
for a real Play Store submission**: Play requires every update to an app be
signed with the same key (or use Play App Signing with a separate upload
key), so whoever owns the production release needs to generate their own
keystore, keep it private and backed up, and set `KEYSTORE`, `KEY_ALIAS`,
`KEYSTORE_PASS` env vars before running `build.sh` — never reuse the
keystore this script generates for a real release, since its passphrase is
visible in this file's own defaults.

The shipped `release/*.apk`/`*.aab` in this repo are signed with the
throwaway key `build.sh` generates. `apksigner verify` confirms v3-scheme
validity (correct for `minSdkVersion=29`); see
[09-STROMEX-ANDROID-VERIFICATION-REPORT.md](./09-STROMEX-ANDROID-VERIFICATION-REPORT.md)
for the full verification transcript.

## Backend connectivity

The WebView serves the app's own bundle from `https://stromex.local` (see
`MainActivity.serveAsset()`) but makes real network calls to whatever
`NEXT_PUBLIC_API_URL` was baked in at web-build time (default
`http://localhost:8000`, same as the browser app). Two things follow:

1. **CORS**: the backend's `CORS_ORIGINS` must include `https://stromex.local`
   (see `apps/api/.env.example`). Without it, every `fetch()` from the app
   fails a CORS preflight.
2. **Reachability**: for a real device, `http://localhost:8000` means *the
   phone's own* localhost, not your workstation's. Point `NEXT_PUBLIC_API_URL`
   at your deployed backend (see `infra/DEPLOYMENT.md`) or, for an emulator on
   the same machine as the backend, `http://10.0.2.2:8000`.

This build's shipped `release/*.apk`/`*.aab` were built with
`NEXT_PUBLIC_API_URL=http://localhost:8000` — **they will only reach a
backend running on the device's own localhost**. This sandbox has no way to
expose a public tunnel to its backend (every tunnel method tried —
Cloudflare Quick Tunnel, ngrok, raw SSH tunnels — is blocked by the same
network policy), so a build pointed at a real public backend URL could not be
produced or tested end-to-end here. See
[09-STROMEX-ANDROID-VERIFICATION-REPORT.md](./09-STROMEX-ANDROID-VERIFICATION-REPORT.md)
for exactly what was and wasn't verified as a result.
